# 한국 맞춤 플레이북 부록 — 돈 버는 개발

이미 사업 아이템이 있는 스타트업 개발자 기준. 전사 피벗 교훈이 아니라 기능/스프린트 단위로 적용 가능한 교훈 위주.

## 1. 한국 스타트업 사례 → 개발자 적용 교훈

### 토스 — 단일 기능 집중, 퍼널 단계 수 줄이기
간편송금 하나로 사용자를 확보한 뒤 확장. "받는 사람→금액→인증" 3단계로 공인인증서/ActiveX 흐름을 제거하는 데만 집중했다.
- 신규 기능 추가보다 **핵심 전환 플로우의 단계 수를 줄이는 것**이 ROI가 높을 때가 많다. 가입/결제/온보딩이 3단계를 넘으면 먼저 진단하라.
- 기능 게이트: "핵심 미션과 직결되는가?" 아니면 로드맵에서 뺀다.

### 당근마켓 — 좁은 세그먼트에서 신뢰 검증 후 확장
판교 반경 6km에서 신뢰를 먼저 검증한 뒤 확산. 해외 진출도 "국내 학습을 로컬 문화에 맞게 변형"하는 원칙을 반복.
- 신기능을 전량 배포하지 말고 **가장 좁은 세그먼트(지역/코호트/플랜)에 롤아웃해 신뢰·리텐션 검증 후 확장**. 피처 플래그 + 코호트 점진 배포가 기술적 구현체.
- 타 세그먼트/해외 확장 시 "그대로 복붙" 금지 — 로컬 재검증 스프린트를 로드맵에 명시.

### 배달의민족 — 자동화 전에 수작업
초기엔 전단지를 새벽마다 수거해 하루 1,000장씩 스캔하며 DB를 만들었다. 자동화는 수요 검증 후.
- 자동 매칭/추천/정산 류 기능은 **수작업·스프레드시트·Wizard-of-Oz로 먼저 운영해 수요 확인 후 개발**.
- 개발 착수 기본 게이트: "이 개발 리소스로 수동 운영 1~2주를 해보면 답이 바로 나오는가?"

### 무신사 — 신뢰 채널에 수요를 먼저 흘려본다
커뮤니티(2001) → 매거진(2005) → 커머스(2009). 신뢰 기반이 생긴 뒤에야 스토어를 얹었다.
- 커뮤니티/콘텐츠성 트래픽이 있다면 유료 기능을 "차갑게" 붙이지 말고 기존 신뢰 채널로 수요를 먼저 측정.
- 수익화 기능 우선순위 신호: "커뮤니티에서 이미 반복적으로 나온 요청인가?"

### 쿠팡 — "계획된 적자"의 조건은 개선 추세
로켓배송 첫해 영업손실 약 30배 증가를 "미래 이윤 투자"라 불렀지만, 핵심은 **손실이 줄어드는 방향의 유닛 이코노믹스 곡선을 추적하며 투자**했다는 것.
- 기능/캠페인 단위로 CAC·LTV·마진을 쪼개 봐라. 적자가 허용되는 건 개선 추세일 때뿐 — 구조적으로 고정/악화면 그냥 적자다.
- 대시보드에 코호트별 마진 추이 필수. "매출 증가 + 마진 정체/악화" = 확장성 없는 보조금 구조 경고.

### 실패 패턴 — 검증 없는 과잉개발
국내 실패 스타트업의 공통점: 고객 문제 검증보다 솔루션 구축을 먼저 함. 풀러스는 사용자 100만·누적 220억 투자에도 폐업. 투자 이력 스타트업 폐업 2021년 104곳 → 2024년 170곳. 실리콘밸리 쪽 원인 분석의 premature scaling(검증 전 조직·인프라 확장)과 동일 계열.
- 기획서/PR에 **"이 기능이 해결하는 문제를 어떤 증거(문의 로그·이탈 데이터·인터뷰)로 확인했는가" 필드를 필수화**.
- 투자금/지원금의 여유가 오히려 "검증 없는 과잉개발"의 방아쇠가 된다 — 국내 반복 패턴.

## 2. 한국 책/콘텐츠

- **그로스해킹 (양승화, 위키북스)**: AARRR을 "각 단계 데이터 측정 + A/B 개선"의 통합 방법론으로. 병목이 획득인지 리텐션인지부터 진단 — 리텐션이 새는데 획득에 돈 쓰는 게 최빈 낭비. Revenue는 반드시 채널별로 분리해 ROI 모델링.
- **린 분석 (Lean Analytics 한국어판, 한빛미디어)**: 단계별 OMTM. 매출 단계 이상이면 ARPU/ARPPU를 전사 단일 대시보드에. 기능 하나당 "5단계 중 어느 단계 지표를 움직이는가"를 명시 — 여러 단계 동시 타겟은 검증이 흐려진다.
- **미디어/커뮤니티**: 아웃스탠딩(실무자 언어 큐레이션), EO/이오플래닛(창업가 인터뷰·B2B 프레임워크), 커리어리(실무자 커리어 SNS, B2B 세일즈/그로스 사례), 디스콰이엇(메이커 소셜 — 자체도 사이드프로젝트에서 6개월 만에 시드 유치).

## 3. 한국 시장 특수성

### 시장 규모 한계 → 국내 검증 후 글로벌
당근 원칙: 국내에서 배우고 고도화한 경험으로 진출하되 서비스를 복붙하지 않고 로컬 변형(하이퍼로컬). 해외/타 세그먼트 확장 시 결제수단·신뢰 메커니즘·UX 관습 재검증 스프린트를 별도로 잡는다.

### 네이버/카카오 플랫폼 의존 리스크
- 네이버 자사우대(2020년 공정위 과징금 약 267억)로 경쟁사 유입이 1% 미만에 머문 사례. 카카오도 카카오톡 아웃링크 결제를 구글 정책 위반으로 삭제(2022).
- 플랫폼 노출·정책 의존 매출은 **SPOF로 취급**하고 자체 채널(이메일·앱 푸시·자체 SEO) 비중을 병행 지표로 추적.
- 플랫폼 위 결제/딥링크 기능은 "정책 위반으로 강제 삭제될 가능성"을 사전 리스크 항목으로 — 대기업도 당했다.

### 결제/구독 (확인 시점: 2025~2026년, 변동 가능)
- 인앱결제 강제방지법(2021.9 시행) 후에도 제3자결제 수수료 최대 ~26% — 법이 있어도 실질 절감은 제한적임을 전제로 가격 설계.
- PG 비교는 수수료율+정산주기+연관리비 합산 실질 비용으로 (토스페이먼츠 카드 ~3.4%+연관리비 수준, B2C 전환율 UX 강점). 초기엔 포트원류 결제 게이트웨이로 시작해 전환 비용을 낮춘다.
- 모바일 웹 결제 유도(아웃링크)는 마켓 정책 위반 리스크 상존.

### B2B SaaS — 도입품의/전자결재 문화
- 엔터프라이즈 딜은 50~90일(SMB ~20일). 실무진 설득만으론 안 되고 경영진·재무·보안·구매를 각각 통과해야 하며, 내부 챔피언 확보가 클로징 핵심.
- **"결재를 통과시키는 기능"(ISMS 등 보안 인증, 온프레미스/VPC 옵션, 세금계산서·전자결재 연동)이 핵심 기능보다 매출 전환에 더 기여하는 경우가 흔하다** — 백로그 우선순위에 명시적으로 반영.

### 정부지원사업 (TIPS, 예비창업패키지 등)
- TIPS는 분할 지급·입금 시점 예측 어려움 — 즉각 현금이 필요한 팀에 부적합.
- 함정: 지원금 소진 자체가 목적이 되는 "좀비" 패턴, 과제 계획서와 실제 로드맵의 괴리 → 개발 리소스가 보고서용 기능에 소모.
- 신청 전 체크 1번: **"이 과제가 요구하는 산출물이 우리 유닛 이코노믹스 개선에 실제로 기여하는가?"**

## 4. 1인 개발/사이드프로젝트 수익화 패턴

- 지배적 패턴은 "단일 앱 대박"이 아니라 **여러 개를 빠르게 만들어 실패에서 배우고 다음에 반영하는 반복 사이클** (디스콰이엇 커뮤니티 공통 관찰: 3개 실패 후 4번째 성공, 월 300만 원 등).
- 기존 제품 팀 적용: "신기능 여러 개를 낮은 완성도로 빠르게 실험 → 반응 좋은 것만 정교화"를 내부 프로세스로.
- 카카오톡 채널: 무료 개설 + 알림톡/주문·배송 알림 — 별도 CRM 없이 국내향 리텐션 채널로 활용 가능.
